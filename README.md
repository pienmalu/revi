# れび（revi）

PDFを送り直すたびに、どの版にどのコメントが付いたか分かりにくくなります。
れびは研究室のPDFを版ごとに保存し、ブラウザで添削するアプリです。
論文は共著者の確認と提出の記録まで、スライドは版の管理と添削まで扱います。

研究室のメンバーと論文が増え、教授からも原稿の進み具合や業績を一か所で把握したいという話がありました。
これも、れびを作ったきっかけです。

## 論文と業績の管理

論文ごとにPDFの版、著者、提出先、締切、共著者の確認状況、提出の記録をまとめます。
一覧では添削中や提出済みの論文を見分けられ、著者や年でも絞り込めます。

提出済みの論文は発表年月などを補い、研究室HP向けの業績リストや、卒論・修論で使うBibTeXとして書き出せます。
一覧はExcelやCSVでも保存できます。
研究室HPへの反映は、書き出した内容を確認してから手動で行います。

## サンプルで試す

Node.js 22.22.0以上と、`package.json` に指定したpnpmを使います。
初回は空のローカルDBに、架空の資料を3件作れます。

```bash
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm seed:samples
pnpm dev
```

一覧には「添削中の論文」「提出済みの論文」「発表スライド」が並びます。
添削中の論文には2つの版とコメントがあり、返信や共著者の「確認OK」を試せます。
提出済みの論文には架空の受領メールを添えています。
PDFの本文は英語の短い例文で、実在の研究や人物の情報は含みません。

サンプル作成は空のDBでだけ実行できます。
既存の資料やメンバーがあるDBでは停止し、内容を書き換えません。
`DATABASE_URL` が空ならDBは `data/pglite`、`BLOB_READ_WRITE_TOKEN` が空ならファイルは `data/files` に保存します。
この2つの値を設定せず、手元の保存先で試してください。

## 使い方

1. 画面の「PDFを追加」を押すか、SlackでPDFとボットへのメンションを同じ投稿に入れます。
2. 資料を開き、文字や範囲を選んでコメントします。
   全体へのコメントや返信も書けます。
3. 元の原稿を直して新しいPDFを送ると、送信者と本文の類似度をもとに版を判定します。

ブラウザではPDF本文を書き換えません。
版の判定が違っていたら、Slackのボタンか画面の「…」から、別の資料に分けたり、ほかの資料の版に移したりできます。

本文が同じ書き込みPDFは、該当する版のコメントとして取り込みます。
読み取れない書き込みはPDFとして保存し、コメントから開けるようにします。

## 論文の確認と提出

筆頭著者以外の共著者が、最新版に「確認OK」を出します。
v3が最新版なら、v1やv2の確認は不要です。
新版を追加すると、その版で確認を取り直します。

著者は、PDFの1ページ目にある登録済みの名前から推定します。
読み取れなければ送信者を仮の著者にするため、情報欄で著者と順番を確認してください。
人が直した著者一覧は、その後の自動判定では変更しません。
Slackの利用者は本名や表示名と照合して結び付けますが、全員のSlackアカウントが最初から分かる仕組みではありません。

学会などへの提出は本人が行います。
提出後に受領メールやスクリーンショットを添え、「提出を報告」で記録します。
確認がそろう前に提出した場合は理由も必要です。

## スライド

横長PDFをスライドと判定します。
スライドには確認OK、提出、締切の催促はなく、版を追加して添削できます。
縦長のスライドなどを手動で分類する機能はありません。

## Slackへの通知

コメントの追加や返信、対応状況の変更、題名の編集では通知しません。
Slackにひも付いた資料では、次の操作や時期に投稿します。

| 操作や時期               | 投稿内容                                                         |
| ------------------------ | ---------------------------------------------------------------- |
| PDFを送る                | スレッドに受付とリンク。別スレッドから送った場合は送信元にも返信 |
| 確認OK                   | スレッドに確認状況。全員そろうと完了のお知らせを追加             |
| 提出を報告               | チャンネルとスレッドに投稿。確認した共著者をメンション           |
| 締切の7日前、3日前、前日 | 未確認の共著者をスレッドでメンション                             |
| 締切後も提出報告がない   | 筆頭著者をスレッドで一度メンション                               |

締切通知には定期処理の設定が必要です。
Slack IDが分からない人は名前だけを表示します。
未確認で提出した場合は、理由と未確認者もスレッドに残ります。
確認依頼のDMはなく、提出報告の記録に失敗したときだけ、操作した本人へのDMを試みます。
端末の音やバナーは、各自のSlack通知設定によります。

## 研究室用リンク

**研究室用リンク**は、推測しにくい鍵を含む共有URLです。
リンクを知る人が閲覧や編集を行い、一度開いたブラウザは鍵を記憶します。
個人ログインはなく、Web画面の名前は自己申告です。

最初のリンクはサーバーログに表示され、Slackのリンクにも鍵が入ります。
外部に漏れた場合は「研究室用リンク」から作り直し、共有先を差し替えてください。
古い鍵は使えなくなります。

## Slackを手元で試す

[開発用の設定](slack-manifest.dev.yaml)で作成したSlackアプリをテスト用チャンネルに招待します。
`.env.local` に `SLACK_BOT_TOKEN`、`SLACK_APP_TOKEN`、ランダムに生成した `SLACK_DEV_SIGNING_SECRET` を設定し、別のターミナルで中継を起動します。

```bash
pnpm slack:dev
```

Webアプリと中継の両方を起動したまま使います。
`.env` の値は `.env.local` に同じ項目があると上書きされるため、トークンの空欄を残さないでください。

開発時の構成、公開条件、モノレポへの移行は [開発用の補足](docs/maintenance.md) にまとめています。
